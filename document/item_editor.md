# アイテムエディター

Python 3.9以上とTkinterで動作します。リポジトリのルートで起動してください。

```sh
python helper/item_editor.py
```

Windows/macOSの通常のPythonインストーラーはTkinterを含みます。LinuxでTkinterがない場合は、OSのパッケージ管理からTkinter（例: Debian/Ubuntuの`python3-tk`）を追加してください。追加のpipパッケージは不要です。

テーブルは比較・選択用、編集ペインは入力用です。Tkinter標準のTreeview・Entry・Comboboxを通常のレイアウトで配置し、セル上に入力部品を重ねません。

## 操作

1. **追加**: `fried_egg`のような代表名を入力します。小文字英字で始まり、英小文字・数字・アンダースコアが使用できます。追加時に `source/main/resources/assets/culinary_expansion/textures/item/<代表名>.png` が存在しなければ、16×16の透過付きインデックスパレットPNG仮画像（8bitインデックス、3色パレット、透明背景、黒い輪郭の白い円盤）を生成します。既存の同名画像は上書きせず使用します。追加後、画像を編集して仕上げられます。
2. **アイテムの行を選択**すると、右側に全属性の入力欄が表示されます。左列に表示・食事、右列に調理・クラフトを二段組みでラベル付きで並べ、素材9マスは3×3で表示します。属性を選び直す操作はありません。必要な値を直接編集し「変更を反映」で一覧を更新します。「変更を取消」で未反映の入力を戻します。入力欄は縦スクロールできます。
3. **保存**: 全アイテムの設定を1つのJSONに保存します。標準のプロジェクトファイルは`source/items_project.json`です。開く・名前を付けて保存にも対応します。
4. **定義へ反映**: JSONを保存し、Java・表示定義・モデル・翻訳・レシピ・レシピ本の解放条件を生成します。両方のHTML一覧も更新します。
5. **テクスチャ取込**: 選んだPNGを代表名の画像ファイルとして配置します。編集ペイン上部に画像・ファイル名・寸法を常時表示します。画像欄の「画像を取り込む」からも取り込めます。
6. **削除**: 確認後、現在のプロジェクトを反映し、対象アイテムの関連生成定義を削除します。テクスチャPNGは保持します。
7. 最後に`python helper/build_deliverable.py`でMODを再ビルドします。

JSON保存だけではゲーム用定義は変わりません。「定義へ反映」で生成するか、`python helper/build_deliverable.py`を実行してください。ビルドスクリプトは保存済みJSONから定義・一覧を自動生成してからGradleを実行します。代表名を変更するとID・識別子・ファイル名も変更され、旧定義は反映時に削除されます。旧画像は保持されるため、新しい代表名へ必要な画像を取り込んでください。

## 編集項目

- 代表名、日本語名、英語名、最大スタック数
- 満腹度、隠し満腹度係数、満腹時使用、食事時間（秒）
- 追加効果: なし・移動速度上昇・再生能力・耐火・暗視・攻撃力上昇・毒・空腹・衰弱
- 効果時間（tick）、効果レベル（1始まり）、確率（0～1）。「なし」の場合は未使用
- 使用後の残り物: なし・ボウル・ガラス瓶・バケツ
- かまど・燻製器の対応、共通の基準調理時間（tick）、経験値、調理出力個数、調理素材
- 焚き火: `不可`または調理時間のtick数
- クラフト方式: クラフト不可・定型・不定形、出力個数
- クラフト素材: 行:列の順で1:1～3:3。空きマスは`不要`。不定形は空きマスを除いた材料群を生成

素材は`minecraft:egg`などのアイテムID、タグは`#minecraft:...`の形式で指定します。IDの書式は検証しますが、指定した素材がゲーム内に存在するかはゲームで確認してください。

## 自動生成と保護

IDは`culinary_expansion:<代表名>`、Java識別子は代表名の大文字、モデルとテクスチャは`<代表名>.json`・`<代表名>.png`です。アイテムIDはテーブル先頭列に表示します。自動生成される識別子・パスは、行を選択すると右側で確認できます。

`ModItems.java`と`CulinaryExpansion.java`、各アイテムのリソースは生成物です。編集元のJSONを変更してください。`generated_files`は同じJSON内の管理情報で、削除対象を制限するために使用します。テクスチャはこの管理対象に含めません。手動の別レシピ・別翻訳キーは保持します。生成途中で失敗した場合、定義ファイルとJSONを元に戻します。

現在のエディターは食品アイテムと各1種類の定型/不定形クラフトを扱います。複数の独自クラフトレシピや独自アイテムクラスの編集は対象外です。

アイテムの行を選択し、ツールバーの「上へ」「下へ」で登録順を変更できます。「保存」でJSONのアイテム配列に順序を保存します。編集中の入力がある場合は「変更を反映」または「変更を取消」を行ってから移動してください。

画面上部の「プロジェクトバージョン」でプロジェクト全体のメタ情報を編集し、「保存」でJSONの`version`を保存します。この値は人間が必要に応じて更新し、アイテム編集やビルドによる自動変更はありません。JAR名・MODメタ情報・配布ページのバージョン表示に使います。旧JSONで値がない場合は`0.1.0`として読み込みます。

編集ペインの「組込み」チェックボックスで、アイテムごとの有効・無効を切り替えます。「変更を反映」→「保存」でJSONの`enabled`を保存します。無効なアイテムは編集元・画像・モデル・レシピなどの関連ファイルを保持します。Java登録と翻訳には有効なアイテムだけを反映し、JARのリソース収録時に無効なアイテムの関連ファイルと、それを材料に含むレシピを除外します。再度有効にすれば定義を生成できます。`enabled`がない旧JSONは、満腹度回復量が0より大きければ有効、それ以外は無効として読み込みます。保存済みのオン・オフは、満腹度を編集しても自動変更しません。

## 検証

```sh
python -m unittest discover -s helper -p test_item_project.py
```

保存・名称変更・定義削除・画像保持・クラフト生成・入力検証・失敗時の巻き戻しを検証します。

## クラフト素材の選択

各マスの「素材を選択」で、画像・表示名・素材IDの一覧を開きます。名前やIDで検索し、ダブルクリックまたは「選択」で入力欄へ設定します。「不要」も選択できます。設定後は編集ペインの「変更を反映」を押してください。タグや他MODの素材IDは引き続き直接入力できます。

公式素材は、ビルドで取得済みの対象MinecraftバージョンのローカルリソースJARから読み込みます。素材画像をリポジトリへコピーしたり、ネットから追加取得したりしません。リソースがない環境では自作アイテムの一覧を使えます。「Minecraft JARを指定」からクライアントリソースを含むJARを指定することもできます。通常の2Dテクスチャのみ表示し、立体・複合モデルは「画像なし」で選択できます。

## 公式食料の参考値

ツールバーの「公式食料の参考値」で、Minecraft 26.3の40種類の食料を別ウィンドウに表示します。表示名・ID・満腹度・アイコン数・隠し満腹度係数・隠し満腹度回復量・満腹時使用を比較できます。名前とIDで検索し、列見出しで昇順・降順に並べ替えられます。エディターを操作しながら開いておけます。

参考データは対象バージョンの公式 `Foods` 定義から取得した `source/vanilla_food_reference.json` です。ネット接続やビルド済みリソースがなくても参照できます。ケーキなどブロックとして食べるものや追加効果の情報は含みません。Minecraftの対象バージョンを変更した場合は参考データも更新してください。

## レシピとMODへの反映

全アイテムは食品として生成し、クリエイティブの「食べ物と飲み物」タブに登録します。各アイテムの有効な調理元素材・クラフト素材のいずれかを入手すると、そのアイテムの全レシピがレシピ本に追加されます。無効な調理方法の元素材やクラフト不可の素材欄は解除条件に含めません。重複素材は一つにまとめます。素材タグも対応します。定型は指定配置を空白の外周を除いて生成し、不定形は配置を問いません。2×2に収まるレシピは所持品でも作れます。3×3が必要な定型や5素材以上の不定形は作業台が必要です。

編集ペインの「変更を反映」→「保存」→`python helper/build_deliverable.py`で配布JARを更新し、MinecraftのmodsフォルダのJARを置き換えて再起動してください。ビルド時には保存済みプロジェクトから定義を自動生成するため、定義の生成忘れによる古いアイテム構成のビルドを防ぎます。

クラフトレシピ本のカテゴリはMinecraftの仕様に従い `misc`、調理レシピのカテゴリは `food` を生成します。これはアイテムをクリエイティブの「食べ物と飲み物」に登録する設定とは別です。クラフトで `food` を指定するとワールド読み込み時のレジストリ登録に失敗するため、配布JAR生成時にカテゴリを検証します。
